## 系统整体架构

### 架构图
```
┌─────────────────────────────────────────────────────────────┐
│                         前端 (Vue 3)                          │
├─────────────────────────────────────────────────────────────┤
│  Chat.vue (主视图)                                            │
│  ├── ConversationItem (对话列表项)                           │
│  ├── ChatHeader (聊天头部)                                    │
│  ├── MessageList (消息列表)                                  │
│  ├── MessageInput (消息输入框)                               │
│  └── ChatInfoPanel (信息侧边栏)                              │
├─────────────────────────────────────────────────────────────┤
│  WebSocket (Socket.IO) + REST API (Axios)                   │
├─────────────────────────────────────────────────────────────┤
│                    后端 (Flask + SocketIO)                    │
├─────────────────────────────────────────────────────────────┤
│  api/v1/chat.py (REST API - 20+个端点)                     │
│  api/v1/live_socket.py (WebSocket 事件处理)                 │
├─────────────────────────────────────────────────────────────┤
│                  数据库 (SQL Server + SQLAlchemy)             │
├─────────────────────────────────────────────────────────────┤
│  核心表: Conversation, ConversationMember, IMMessage等      │
└─────────────────────────────────────────────────────────────┘
```

### 系统分层
```
表现层 (Vue 3 + Element Plus)
    ↓
通信层 (Socket.IO WebSocket + Axios REST API)
    ↓
应用层 (Flask REST API + WebSocket事件处理)
    ↓
数据访问层 (SQLAlchemy ORM)
    ↓
数据存储层 (SQL Server)
```

## 数据库设计

### 核心表结构分析

#### 1. **Conversation 表** (对话表)
**用途**: 存储所有类型的对话（私聊、群聊、班级群组、课程群组、直播课堂）

**关键字段**:
```
id (BigInteger)                    # 主键，自生成
conversation_type (String)         # 对话类型: 'private'|'group'|'class_group'|'course_group'|'live_class'
title (String)                     # 对话标题（群组名称，私聊为空）
avatar (String)                    # 群组头像URL
description (Text)                 # 群组描述

# Telegram 式群组功能
group_subtype (String)             # 'normal'|'channel'|'discussion'（频道、讨论组等）
conversation_subtype (String)      # 对话子类型标签，如 'live_class_discussion'
linked_discussion_id (BigInteger)  # 频道绑定的讨论组ID
linked_channel_id (BigInteger)     # 讨论组关联的频道ID

# 关联信息
created_by (BigInteger)            # 创建者用户ID
class_id (BigInteger)              # 课程班级关联
live_class_id (BigInteger)         # 直播课堂关联

# 状态
is_archived (Boolean)              # 是否归档
is_active (Boolean)                # 是否活跃

# 时间戳
created_at, updated_at, last_message_at
```

**设计要点**:
- ✅ 支持多种对话类型（私聊、群聊、班级群组等）
- ✅ 支持 Telegram 式的频道和讨论组
- ✅ 支持对话归档和软删除
- ⚠️ 可能需要添加对话成员计数字段以提升性能

---

#### 2. **ConversationMember 表** (成员关系表)
**用途**: 管理用户与对话的关系、权限和个人设置

**关键字段**:
```
id (BigInteger)                    # 主键
conversation_id (BigInteger)       # 对话ID（外键）
user_id (BigInteger)               # 用户ID（外键）

# 角色和权限
role (String)                      # 'owner'|'admin'|'member'

# 个性化设置
is_muted (Boolean)                 # 是否静音
is_pinned (Boolean)                # 是否置顶
custom_alias (String)              # 自定义备注名

# 阅读状态
last_read_message_id (BigInteger)  # 最后已读消息ID
last_read_at (DateTime)            # 最后阅读时间
unread_count (Integer)             # 未读计数

# 草稿
draft_content (Text)               # 草稿内容
draft_updated_at (DateTime)        # 草稿更新时间

# 时间戳
joined_at, left_at                 # 加入和离开时间
```

**唯一约束**:
```sql
UNIQUE (conversation_id, user_id)  # 每个用户在每个对话中只能有一条记录
```

**设计要点**:
- ✅ 支持细粒度的权限控制（owner, admin, member）
- ✅ 支持个人化设置（静音、置顶、备注名）
- ✅ 支持消息草稿保存
- ✅ 清晰的阅读状态追踪
- ⚠️ left_at 字段实现"软删除"，为空表示仍在群组

---

#### 3. **IMMessage 表** (消息表)
**用途**: 统一存储所有类型的消息（文本、图片、文件、系统消息等）

**关键字段**:
```
id (BigInteger)                    # 主键
conversation_id (BigInteger)       # 对话ID（外键）
sender_id (BigInteger)             # 发送者ID（外键）

# 消息内容
message_type (String)              # 'text'|'image'|'file'|'voice'|'video'|'system'|'emoji'
content (UnicodeText)              # 文本内容（支持完整Unicode和Emoji）

# 媒体文件
media_url (String)                 # 媒体文件URL
file_name (String)                 # 原始文件名
file_size (BigInteger)             # 文件大小（字节）
mime_type (String)                 # MIME类型

# 引用和回复
reply_to_id (BigInteger)           # 回复的消息ID（兼容旧系统）
forward_from_id (BigInteger)       # 转发来源消息ID

# Telegram 式群组功能
root_message_id (BigInteger)       # 频道讨论：指向频道消息ID
parent_message_id (BigInteger)     # 普通群引用回复：指向父消息ID
comment_count (Integer)            # 评论数量（冗余字段，提升性能）

# 扩展元数据
extra_data (JSON)                  # 提及用户列表、链接预览等

# 状态标记
is_edited (Boolean)                # 是否已编辑
is_deleted (Boolean)               # 是否已删除
is_pinned (Boolean)                # 是否置顶

# 时间戳
created_at, edited_at, deleted_at
```

**支持的消息类型**:
- 📝 **text**: 普通文本消息
- 🖼️ **image**: 图片消息（URL存储在media_url）
- 📄 **file**: 文件消息（支持任意格式）
- 🎵 **voice**: 语音消息
- 🎬 **video**: 视频消息
- 🔔 **system**: 系统消息（成员加入、变更权限等）
- 😊 **emoji**: 表情消息

**设计要点**:
- ✅ 使用 UnicodeText 完全支持 Emoji 和各种语言
- ✅ 灵活的 extra_data JSON 字段用于扩展功能
- ✅ 支持消息编辑和软删除
- ✅ 支持 Telegram 式的频道讨论和线程回复
- ✅ comment_count 冗余字段提升性能

## 实时通信设计

### Socket.IO 架构

```
客户端 (Vue 3)
    ↕ WebSocket
Socket.IO Server (Flask-SocketIO)
    ↕ Flask 应用
    ↓
数据库 (SQLAlchemy)
```

### 事件流程

#### 发送消息流程
```
1. 用户在 MessageInput 输入消息，按 Enter
   ↓
2. 前端验证消息内容不为空
   ↓
3. 前端发出 REST API 请求: POST /chat/conversations/:id/messages
   ↓
4. 后端处理请求:
   - 验证用户权限
   - 保存消息到数据库
   - 创建 @ 提及通知
   ↓
5. 后端通过 WebSocket 广播消息给所有在线成员
   socket.emit('chat:new_message', message_data)
   ↓
6. 前端收到消息，实时更新:
   - 添加消息到消息列表
   - 更新对话的最后消息
   - 自动滚动到底部
   ↓
7. 前端发出 WebSocket 事件标记已读
   socket.emit('chat:mark_read', message_id)
```

#### 消息编辑流程
```
1. 用户点击消息上下文菜单，选择"编辑"
   ↓
2. 消息内容加载到输入框
   ↓
3. 用户修改内容，按 Enter
   ↓
4. 前端发出 REST API 请求: PUT /chat/messages/:id
   ↓
5. 后端更新数据库，标记 is_edited=True
   ↓
6. 后端广播消息编辑事件: chat:message_edited
   ↓
7. 前端更新消息显示，添加"(已编辑)"标签
```

## 需要改进的地方

### 1. **数据库设计**

⚠️ **问题 1: 缺少消息搜索索引**
- **影响**: 消息搜索性能差，尤其是大型对话
- **建议**: 为 content 字段建立全文索引
```sql
-- SQL Server 全文搜索
CREATE FULLTEXT INDEX ON IMMessage(content) 
  KEY INDEX PK_IMMessage
```

⚠️ **问题 2: 缺少对话成员计数缓存**
- **影响**: 获取对话列表时需要计算成员数，性能浪费
- **建议**: 在 Conversation 表中添加 member_count 字段
```python
member_count = db.Column(db.Integer, default=0)
```

⚠️ **问题 3: MessageStatus 表设计可能过于复杂**
- **影响**: 针对每个用户存储状态，导致表数据量巨大
- **建议**: 考虑按批量存储读取用户（如使用 JSON 数组存储读取者列表）

---

### 2. **后端 API 设计**

⚠️ **问题 1: 缺少批量操作 API**
- **影响**: 标记多条消息已读需要多个请求
- **建议**: 添加批量操作端点
```python
POST /chat/conversations/:id/messages/batch-mark-read
DELETE /chat/messages/batch-delete
```

⚠️ **问题 2: 消息搜索 API 缺失**
- **影响**: 无法在对话中搜索历史消息
- **建议**: 添加消息搜索端点
```python
GET /chat/conversations/:id/messages/search?q=keyword
```

⚠️ **问题 3: 缺少消息导出功能**
- **影响**: 用户无法备份或导出对话记录
- **建议**: 添加导出端点（CSV/JSON 格式）

---

### 3. **前端架构**

⚠️ **问题 1: 虚拟滚动可能不够高效**
- **影响**: 大量消息加载时可能卡顿
- **建议**: 优化虚拟列表实现，减少 DOM 节点

⚠️ **问题 2: 缺少消息本地缓存**
- **影响**: 重新打开对话需要重新加载消息
- **建议**: 使用 IndexedDB 本地缓存消息

const db = new Dexie('ChatDB')

- **建议**: 实现本地消息队列，网络恢复后重试

const offlineQueue = []

message.version = db.Column(db.Integer, default=0)

#### A. 实现离线消息队列
```javascript
// messageQueue.js
class MessageQueue {
  constructor() {
    this.queue = []
    this.isSyncing = false
  }
  
  add(message) {
    this.queue.push({
      ...message,
      timestamp: Date.now(),
      retryCount: 0
    })
  }
  
  async flush() {
    if (this.isSyncing) return
    this.isSyncing = true
    
    for (const message of this.queue) {
      try {
        await api.post(`/chat/conversations/${message.conversation_id}/messages`, {
          content: message.content,
          message_type: message.message_type
        })
        this.queue.shift()
      } catch (error) {
        message.retryCount++
        if (message.retryCount > 3) {
          // 放弃重试，显示错误
          showError(`消息发送失败: ${message.content}`)
          this.queue.shift()
        }
      }
    }
    
    this.isSyncing = false
  }
}
```
