# 课堂结束状态显示功能说明

## 功能概述

实现了课堂结束后的状态显示功能，用户无法进入已结束的课堂，并在界面上清晰显示课堂已结束状态。

## 修改内容

### 1. 前端 - MessageList.vue (课堂入口消息卡片)

#### 功能改进：
- **状态徽章显示**：课堂入口卡片现在会显示状态标签
  - 🟢 "进行中" - 课堂正在进行
  - 🔴 "已结束" - 课堂已结束
  
- **视觉反馈**：
  - 进行中的课堂：紫色渐变背景 (`#667eea` → `#764ba2`)
  - 已结束的课堂：灰色渐变背景 (`#9ca3af` → `#6b7280`)，半透明显示
  
- **按钮行为**：
  - 进行中：显示"进入课堂"按钮，可点击
  - 已结束：显示"课堂已结束"文本，无按钮

#### 代码变化：
```vue
<!-- 添加了状态徽章和条件渲染 -->
<div v-else-if="message.message_type === 'live_class_entry'" 
     class="live-class-entry" 
     :class="{ 'class-ended': getClassEntryData(message).status === 'ended' }">
  <div class="entry-header">
    <!-- ... -->
    <span v-if="getClassEntryData(message).status === 'ended'" 
          class="status-badge ended">已结束</span>
    <span v-else-if="getClassEntryData(message).status === 'active'" 
          class="status-badge active">进行中</span>
  </div>
  <!-- ... -->
  <div class="entry-footer">
    <span class="entry-duration">预计 {{ getClassEntryData(message).duration }} 分钟</span>
    <button v-if="getClassEntryData(message).status !== 'ended'" 
            class="entry-join-btn" 
            @click="joinClass(getClassEntryData(message).lesson_id, getClassEntryData(message).status)">
      进入课堂
    </button>
    <span v-else class="ended-text">课堂已结束</span>
  </div>
</div>
```

#### joinClass 方法增强：
- 点击前先检查本地状态
- 调用后端 API 二次验证课堂状态
- 如果课堂已结束，显示提示并阻止进入

```javascript
const joinClass = async (lessonId, status) => {
  // 本地状态检查
  if (status === 'ended') {
    ElMessage.warning('课堂已结束，无法进入')
    return
  }
  
  // API 二次验证
  try {
    const response = await api.get(`/live-class/${lessonId}/check`)
    if (response.data.status === 'ended') {
      ElMessage.warning('课堂已结束，无法进入')
      return
    }
  } catch (error) {
    if (error.response?.status === 403) {
      ElMessage.error(error.response.data.error || '课堂已结束')
      return
    }
  }
  
  // 跳转到课堂页面
  // ...
}
```

### 2. 前端 - ChatHeader.vue (班级群顶部进入课堂按钮)

#### 功能改进：
- 点击"进入课堂"按钮前验证课堂状态
- 如果课堂已结束，显示提示并清除活跃课堂信息

#### 代码变化：
```javascript
const handleJoinClass = async () => {
  if (!activeClassInfo.value) return
  
  const lessonId = activeClassInfo.value.lesson_id
  
  // 验证课堂状态
  try {
    const response = await api.get(`/live-class/${lessonId}/check`)

  } catch (error) {
    if (error.response?.status === 403) {
      ElMessage.error(error.response.data.error || '课堂已结束')
      activeClassInfo.value = null
      return
    }
  }
  
  // 跳转到课堂
  // ...
}
```

### 3. 后端 - live_class.py

#### 新增 API 端点：

##### GET `/api/v1/live-class/<lesson_id>/check`
检查课堂状态的专用接口

**响应：**
```json
{
  "status": "active|ended",
  "title": "课堂标题",
  "start_time": "2026-02-02T10:00:00"
}
```

**错误响应（课堂已结束）：**
```json
{
  "error": "Live class has ended",
  "status": "ended"
}
```
HTTP 状态码：403

#### 修改功能：

##### 1. 开始授课 - 包含状态信息
```python
# 在发送课堂入口消息时，包含 status 字段
content = {
    "lesson_id": lesson_id,
    "title": title,
    "description": description,
    "duration": duration,
    "status": "active"  # 新增
}
```

##### 2. 结束授课 - 更新消息状态
```python
# 结束课堂时，更新所有相关的课堂入口消息状态
import json
all_entry_messages = IMMessage.query.filter_by(message_type='live_class_entry').all()
for msg in all_entry_messages:
    try:
        content = json.loads(msg.content)
        if content.get('lesson_id') == lesson_id:
            content['status'] = 'ended'
            msg.content = json.dumps(content, ensure_ascii=False)
    except:
        pass
```

## 用户体验流程

### 场景1：教师结束授课
1. 教师点击"结束授课"按钮
2. 后端更新 `LiveClass.status = 'ended'`
3. 后端更新所有包含该课堂的入口消息状态为 `"status": "ended"`
4. 前端课堂入口卡片自动变灰，显示"已结束"徽章
5. "进入课堂"按钮变为"课堂已结束"文本

### 场景2：学生尝试进入已结束课堂（通过消息卡片）
1. 学生看到灰色的课堂入口卡片，带有"已结束"徽章
2. 没有"进入课堂"按钮，只显示"课堂已结束"文本
3. 无法点击进入

### 场景3：学生尝试进入课堂（边界情况）
1. 学生在课堂进行中打开了聊天页面
2. 此时教师结束了课堂
3. 学生点击"进入课堂"按钮
4. 前端调用 `/check` API 验证状态
5. 后端返回 403 错误，提示"课堂已结束"
6. 前端显示提示消息，阻止进入

### 场景4：通过班级群顶部按钮进入
1. ChatHeader 组件每30秒检查一次活跃课堂
2. 如果检测到课堂已结束，隐藏"进入课堂"按钮
3. 用户点击按钮时再次验证状态
4. 如果已结束，显示提示并清除活跃课堂信息

## 测试建议

1. **基本流程测试**
   - 开始授课 → 消息显示"进行中" → 结束授课 → 消息显示"已结束"

2. **权限测试**
   - 学生无法进入已结束课堂
   - 教师无法进入已结束课堂（包括自己的课堂）

3. **并发测试**
   - 多个学生同时查看消息
   - 课堂结束时，所有学生都能看到状态更新

4. **边界情况**
   - 课堂进行中途，网页刷新后状态保持
   - 课堂结束后立即点击进入，应被阻止
   - API 验证失败时的降级处理

## 注意事项

1. **状态同步**：课堂入口消息的状态存储在 `content` JSON 字段中，结束课堂时会更新所有相关消息

2. **双重验证**：前端同时依赖本地状态和服务器验证，确保安全性

3. **用户提示**：所有阻止操作都有明确的提示消息

4. **视觉设计**：已结束课堂使用灰色+半透明，清晰区分状态

5. **性能考虑**：状态检查使用轻量级 API，不影响用户体验
