# 在线授课功能详细开发档案

## 引言
本档案基于《在线授课功能实施档案》，聚焦从完成设计到完成代码实现的详细先后步骤和技术细节。目标是提供可操作的开发指南，确保功能按计划高质量交付。

## 1. 架构设计阶段
### 步骤描述
在需求确认后，进行系统架构设计，确保模块化、可扩展。

### 技术细节
- **整体架构**：采用客户端-服务器模式，后端Flask+SocketIO，前端Vue.js+WebRTC。
- **模块划分**：
  - 后端：API层（RESTful）、实时层（SocketIO）、媒体层（WebRTC信令）。
  - 前端：视图层（教师/学生页面）、组件层（画板、聊天）、服务层（Socket客户端）。
- **数据流设计**：用户认证→课堂创建→实时同步→数据持久化。
- **工具**：使用Draw.io绘制架构图，定义接口规范（OpenAPI 3.0）。
- **输出**：架构文档、接口定义文件（YAML）。

### 实现难点及解决方案
- **难点4：状态同步与冲突解决**（教师切换内容时多客户端状态不一致、网络延迟导致操作顺序错乱）。
  - **解决方案**：设计操作日志系统，每个操作带唯一ID和时间戳；服务器维护权威状态，客户端定期同步；使用乐观锁处理冲突。
- **难点5：安全与权限控制**（防止未授权加入、数据泄露）。
  - **解决方案**：架构中集成JWT验证和房间权限检查；WebRTC使用DTLS加密；定义角色-based访问控制（RBAC）。
- **难点6：性能与可扩展性**（高并发数据库瓶颈、前端渲染卡顿）。
  - **解决方案**：架构采用微服务模式，后端使用Redis缓存；前端Canvas虚拟化；规划负载均衡和CDN。

## 2. 后端开发阶段
### 步骤描述
按模块顺序开发后端：先核心API，再实时通信，最后媒体处理。

### 技术细节
- **环境搭建**：创建虚拟环境，安装`flask-socketio==5.3.6`、`flask-cors==4.0.0`、`aiortc==1.6.0`（WebRTC）。
- **数据库模型**：
  ```python
  class LiveClass(db.Model):
      id = db.Column(db.Integer, primary_key=True)
      lesson_id = db.Column(db.String(50), unique=True)
      teacher_id = db.Column(db.Integer, db.ForeignKey('user.id'))
      start_time = db.Column(db.DateTime)
      end_time = db.Column(db.DateTime)
      participants = db.relationship('Participant', backref='live_class')

  class DrawingData(db.Model):
      id = db.Column(db.Integer, primary_key=True)
      live_class_id = db.Column(db.Integer, db.ForeignKey('live_class.id'))
      user_id = db.Column(db.Integer)
      x_percent = db.Column(db.Float)  # 百分比坐标
      y_percent = db.Column(db.Float)
      color = db.Column(db.String(7))
      timestamp = db.Column(db.DateTime)
  ```
- **API端点**：
  - POST /api/live-class/start：创建课堂，发布公告。
  - GET /api/live-class/{id}/join：验证加入权限。
  - POST /api/live-class/{id}/end：结束课堂，生成笔记。
- **SocketIO实现**：
  ```python
  @socketio.on('join_class')
  def handle_join(data):
      join_room(data['lesson_id'])
      emit('user_joined', {'user': current_user.name}, room=data['lesson_id'])

  @socketio.on('drawing')
  def handle_drawing(data):
      # 广播到房间
      emit('drawing_update', data, room=data['lesson_id'], skip_sid=request.sid)
      # 存储到DB
      save_drawing(data)
  ```
- **WebRTC信令**：
  - 使用aiortc实现TURN服务器。
  - 端点：POST /api/webrtc/offer：处理SDP offer，返回answer。
- **安全**：JWT验证所有请求，房间权限检查。
- **测试**：使用pytest测试API，SocketIO客户端模拟连接。

### 实现难点及解决方案
- **难点1：实时画板同步**（坐标在不同分辨率同步、网络延迟导致绘制顺序错乱）。
  - **解决方案**：使用百分比坐标发送；实现时间戳排序重放；添加确认机制和WebSocket压缩。
- **难点2：WebRTC媒体流传输**（信令服务器、NAT穿越、浏览器兼容、带宽限制）。
  - **解决方案**：部署TURN服务器；实现自适应码率；Polyfill兼容性；添加备用音频模式。
- **难点3：SocketIO实时通信**（大规模并发负载高、网络不稳定）。
  - **解决方案**：Redis消息队列；心跳检测自动重连；优化消息格式减少广播。
- **难点8：数据持久化与回放**（实时数据量大、存储复杂）。
  - **解决方案**：分层存储（缓存+压缩）；AI汇总笔记；支持录制回放。

## 3. 前端开发阶段
### 步骤描述
先搭建页面框架，再实现核心组件，最后集成实时功能。

### 技术细节
- **环境搭建**：Vue 3 + Vite，安装`socket.io-client==4.7.2`、`simple-peer==9.11.1`（WebRTC简化）。
- **路由配置**：
  ```javascript
  const routes = [
    { path: '/live-class/:id', component: () => import('@/views/LiveClass.vue'), meta: { requiresAuth: true } }
  ];
  ```
- **教师端页面**：
  - 模板：`<DrawingCanvas ref="canvas" /> <ScreenShare @start="startShare" /> <Chat :messages="messages" />`
  - 脚本：使用Vue Composition API管理状态。
- **学生端页面**：类似，但画板只读。
- **画板组件**：
  ```javascript
  export default {
    mounted() {
      this.canvas = this.$refs.canvas;
      this.ctx = this.canvas.getContext('2d');
      this.socket.on('drawing_update', this.drawFromServer);
    },
    methods: {
      draw(x, y) {
        const rect = this.canvas.getBoundingClientRect();
        const xPercent = (x - rect.left) / rect.width;
        const yPercent = (y - rect.top) / rect.height;
        this.socket.emit('drawing', { x: xPercent, y: yPercent, color: this.color });
      },
      drawFromServer(data) {
        const x = data.x * this.canvas.width;
        const y = data.y * this.canvas.height;
        this.ctx.fillStyle = data.color;
        this.ctx.fillRect(x, y, 5, 5);  // 简化绘制
      }
    }
  };
  ```
- **WebRTC屏幕共享**：
  ```javascript
  async startShare() {
    const stream = await navigator.mediaDevices.getDisplayMedia({ video: true });
    this.peer = new SimplePeer({ initiator: true, stream });
    this.peer.on('signal', data => this.socket.emit('webrtc_signal', data));
    this.socket.on('webrtc_signal', data => this.peer.signal(data));
  }
  ```
- **聊天组件**：使用SocketIO监听'message'事件，发送时emit。
- **响应式**：使用CSS Grid，媒体查询适配移动端。
- **测试**：使用Vue Test Utils单元测试组件，Cypress端到端测试。

### 实现难点及解决方案
- **难点7：跨平台兼容性**（不同浏览器WebRTC/Canvas支持差异、移动端触摸）。
  - **解决方案**：Polyfill库填补兼容；响应式设计适配触摸；测试矩阵覆盖主流环境。

## 4. 集成与测试阶段
### 步骤描述
先单元测试，再集成测试，最后端到端验证。

### 技术细节
- **单元测试**：
  - 后端：pytest + coverage，测试模型CRUD、Socket事件。
  - 前端：Jest，测试组件渲染、事件处理。
- **集成测试**：使用Docker Compose启动全栈，测试API+Socket+DB。
- **端到端测试**：Playwright脚本模拟教师发起、学生加入、绘制、聊天。

- **安全测试**：OWASP ZAP扫描API，验证JWT过期处理。

### 实现难点及解决方案
- **难点1-8**：集成测试阶段重点验证所有难点，通过模拟场景测试解决方案有效性。例如，使用Locust测试性能（难点6）、跨浏览器测试兼容性（难点7）。

## 5. 部署与上线阶段
### 步骤描述
容器化部署，配置监控，逐步上线。

### 技术细节
- **容器化**：
  ```dockerfile
  FROM python:3.9
  COPY . /app
  RUN pip install -r requirements.txt
  CMD ["flask", "run", "--host=0.0.0.0"]
  ```
- **部署**：使用Kubernetes，配置Ingress、Service。WebRTC需UDP端口。
- **监控**：Prometheus监控Socket连接数，Grafana仪表板。
- **上线策略**：蓝绿部署，先小规模测试用户反馈。

### 实现难点及解决方案
- **难点6：性能与可扩展性**（部署后并发压力）。
  - **解决方案**：Kubernetes自动扩展；监控资源使用，动态调整实例。

## 6. 维护与优化阶段
### 步骤描述
上线后监控、优化性能、添加新功能。

### 技术细节
- **日志分析**：ELK栈分析错误模式。
- **性能优化**：Canvas虚拟化（只渲染可见部分），WebRTC自适应码率。
- **用户反馈**：收集反馈，迭代改进（如添加录制功能）。

### 实现难点及解决方案
- **难点1-8**：持续监控和优化所有难点。例如，基于日志分析改进同步算法（难点1）、升级WebRTC库应对新兼容性（难点7）。

此档案提供从设计到实现的完整路径，确保开发团队按步骤执行。
