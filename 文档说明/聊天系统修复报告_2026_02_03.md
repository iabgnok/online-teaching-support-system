### 1. ✅ 修复群组置顶排序问题

**问题描述**：置顶的群组显示在列表底部而不是顶部

**修复位置**：[api/v1/chat.py](api/v1/chat.py#L313)

**修复方案**：
修改了对话列表的排序逻辑，确保置顶对话（`is_pinned=True`）始终排在最前面：

```python
# 修改前
conversations.sort(key=lambda x: (not x['is_pinned'], x['updated_at'] or ''), reverse=True)

# 修改后  
conversations.sort(key=lambda x: (not x['is_pinned'], -(datetime.fromisoformat(x['updated_at']).timestamp() if x['updated_at'] else 0)))
```

**效果**：置顶群组现在正确显示在列表顶部，按更新时间倒序排列

## 潜在问题和解决方案

### 如果学生端仍看不到临时群组

**排查步骤**：

1. **运行诊断脚本**：
   ```bash
   python check_live_conversations.py
   ```
   检查输出，确认：
   - 对话是否被创建
   - 学生是否在成员列表中
   - 成员数量是否匹配

2. **检查数据库**：
   ```sql
   -- 查看活跃课堂对话
   SELECT c.id, c.title, c.conversation_type, c.live_class_id
   FROM conversations c
   WHERE c.conversation_type = 'live_class';
   
   -- 查看特定对话的成员
   SELECT cm.user_id, u.real_name, u.role
   FROM conversation_members cm
   JOIN users u ON cm.user_id = u.user_id
   WHERE cm.conversation_id = [对话ID] AND cm.left_at IS NULL;
   ```

3. **前端调试**：
   - 打开浏览器开发者工具
   - 检查Network标签中`/chat/conversations`的响应
   - 验证响应中是否包含`live_class`类型的对话

4. **强制刷新**：
   - 学生端清除浏览器缓存
   - 退出登录后重新登录
   - 检查WebSocket连接是否正常

### 如果时间显示仍然错误

**排查步骤**：

1. **检查服务器时区**：
   ```python
   # 在Python中检查
   from datetime import datetime
   print(datetime.now())  # 服务器当前时间
   ```

2. **检查浏览器时区**：
   ```javascript
   // 在浏览器控制台
   console.log(new Date())  // 浏览器当前时间
   console.log(Intl.DateTimeFormat().resolvedOptions().timeZone)  // 时区
   ```

3. **统一时区处理**：
   如果服务器和客户端时区不同，可以在后端统一返回UTC时间：
   ```python
   # 修改后端返回格式
   'created_at': message.created_at.isoformat() + 'Z'  # 添加Z表示UTC
   ```
