# 群组列表显示已结束课堂Bug修复报告
**修复日期**: 2026年2月4日

## 🐛 问题描述

学生的群组列表中显示了已结束课堂的临时群组，这些临时群组不应该继续显示在列表中。

### 问题表现
- 学生聊天界面中出现多个相同名称的群组（如"软件工程2025秋01班"）
- 已结束的课堂临时群组仍然可见
- 造成群组列表混乱，影响用户体验

## 🔍 根本原因

在 `/chat/conversations` API 中，获取对话列表时没有过滤掉已结束课堂的临时群组。

**问题代码位置**: `api/v1/chat.py` - `get_conversations()` 函数

### 对话类型说明

系统中的对话类型：
1. **`class_group`** - 永久班级群（应该一直显示）
2. **`live_class`** - 课堂临时群组（只在课堂进行中显示）
   - 关联 `LiveClass` 记录
   - 有 `status` 字段：'active' 或 'ended'
3. **`ended_live_class`** - 旧版本的已结束课堂类型（遗留数据）

## ✅ 修复方案

### 修改内容

**文件**: `api/v1/chat.py` 

在 `get_conversations()` 函数中添加过滤逻辑：

```python
conversations = []

for membership in memberships:
    conv = membership.conversation
    
    # 隐藏讨论组，不在列表中显示（它们只作为频道的评论区存在）
    if conv.group_subtype == 'discussion':
        continue
    
    # 隐藏已结束课堂的临时群组
    # 方式1: live_class类型且课堂已结束
    if conv.conversation_type == 'live_class':
        if conv.live_class_id:
            live_class = LiveClass.query.get(conv.live_class_id)
            if live_class and live_class.status == 'ended':
                continue  # 跳过已结束的课堂群组
    
    # 方式2: ended_live_class类型（旧数据）也应该隐藏
    if conv.conversation_type == 'ended_live_class':
        continue
    
    # ... 继续处理其他对话
```

### 修复逻辑

1. **检查对话类型**: 如果是 `live_class` 类型
2. **查询课堂状态**: 通过 `live_class_id` 查询 `LiveClass` 记录
3. **过滤已结束课堂**: 如果 `status == 'ended'`，则跳过不显示
4. **兼容旧数据**: 同时过滤 `ended_live_class` 类型的对话

## 🔄 课堂生命周期

### 课堂创建时
1. 创建 `LiveClass` 记录（status='active'）
2. 创建对应的 `Conversation` 记录（type='live_class'）
3. 自动添加教师和学生为成员
4. **此时显示在群组列表中** ✓

### 课堂结束时
1. 更新 `LiveClass.status = 'ended'`
2. 更新相关消息状态
3. 删除临时对话及成员记录（可选）
4. **修复后：自动从列表中隐藏** ✓

## 💡 设计说明

### 为什么不删除对话？

课堂结束后不直接删除对话记录的原因：
1. **保留历史**: 需要保留课堂消息记录用于回顾
2. **数据完整性**: `LiveClass` 表通过外键关联 `Conversation`
3. **灵活性**: 可能需要查看历史课堂的聊天记录

### 为什么用过滤而不是修改状态？

1. **兼容性好**: 不需要修改现有的数据结构
2. **实现简单**: 只需在查询时添加过滤条件
3. **易于维护**: 逻辑集中在一个地方
4. **可扩展**: 未来可以添加"查看历史课堂"功能
